# DOMEO · Подбор по корзине

Прототип инструмента: берёт корзину поставщика (Петрович, ВсеИнструменты, Lemana
или свободный список), подбирает аналоги в каталоге **store.domeo.ru** и собирает
из них корзину. Всё работает в браузере менеджера — без доступа к БД и без прокси.

## Как это устроено (поток)

1. Прораб присылает корзину (ссылка Петрович/ВИ/Lemana или список) в мессенджер.
2. Менеджер открывает корзину в браузере.
3. **Чтение позиций** с этой страницы (закладка или расширение).
4. **Подбор аналогов** в каталоге DOMEO через публичный поиск Diginetica.
5. Менеджер проверяет/правит кандидатов.
6. **Сборка корзины** на store.domeo.ru (под логином менеджера) и ссылка на неё.

Два шага (чтение корзины поставщика и запись в корзину DOMEO) обязаны выполняться
в браузере менеджера на самих сайтах — это ограничение браузера (cross-origin и
антибот поставщиков), поэтому их делают закладка/расширение, а не сервер.

## Состав

| Папка | Что это | Где работает |
|---|---|---|
| `webapp/` | Веб-приложение подбора (статическая страница) | любой браузер |
| `bookmarklets/` | Закладки: «Прочитать корзину» и «Собрать корзину» | любой браузер |
| `extension/` | Расширение Chrome/Яндекс (всё в одном окне) | только Chromium |

- **Любой браузер** → `webapp` + `bookmarklets`.
- **Один клик, но только Chromium** → `extension` (читает страницу, подбирает и
  собирает корзину сам, сразу показывает ссылку; есть словарь соответствий и история).

## Запуск

### Веб-приложение
Статическая страница, бэкенд не нужен — подбор идёт из браузера.
- Локально: `cd webapp && python -m http.server 8777`, открыть `http://localhost:8777`.
- На сервере (stage): положить содержимое `webapp/` как статику, открыть по URL.

### Закладки
Откройте `bookmarklets/install.html` и перетащите кнопки на панель закладок.

### Расширение
`browser://extensions` (или `chrome://extensions`) → Режим разработчика →
«Загрузить распакованное» → папка `extension/`.

## Деплой на Kubernetes (stage) — под конвенцию Domeo-Infra (GitOps/ArgoCD)

Приложение — статика в nginx-контейнере (слушает **8080**). Модель как в Domeo-Infra:
образ в GHCR, манифесты в GitOps-репозитории, доставка через ArgoCD.

1. **Образ.** CI репозитория (`.github/workflows/build.yml`) собирает образ и пушит в
   GHCR: `ghcr.io/<owner>/domeo-basket-matcher`. Нужен образ в GHCR организации —
   зеркалируется платформенным `image-mirror`.
2. **Манифесты.** Содержимое `deploy/k8s/` (`deployment.yaml`, `ingress.yaml`) кладётся в
   `Domeo-Infra` по пути `deploy/services/stage/<product>/<service>/manifests/`.
   Продукт/namespace/host задаёт платформа (разрешённые продукты: `crm`, `cfg`, `cad`, `id`);
   в манифестах стоят предположения (`crm-stage`, `podbor.test.domeohome.ru`) — **уточнить**.
   `Application` создаёт платформенный ApplicationSet; вручную его не добавляют.
3. **Доставка.** ArgoCD синхронизирует каталог сервиса (`selfHeal` / `prune`).

Конвенции, уже учтённые в манифестах:
- контейнер слушает **8080**, Service `80 → 8080`;
- аннотация `reloader.stakater.com/auto: "true"`, readinessProbe на `/`;
- Ingress: `ingressClassName: traefik`, `cert-manager.io/cluster-issuer: letsencrypt`,
  stage-зона `*.test.domeohome.ru`, TLS включён.

`Dockerfile` — `nginx:1.27-alpine`, отдаёт `webapp/`; `deploy/nginx.conf` — security-заголовки
(CSP, X-Frame-Options, nosniff, Referrer-Policy) + `/healthz`. HTTPS обязателен (приложение
ходит в Diginetica по https).

Сборку образа в GHCR-организации и перенос манифестов в Domeo-Infra делает ваш CI/платформа —
здесь нет доступа к GHCR организации и к кластеру.

## Безопасность (защита от вставки скриптов)

Веб-приложение защищено от XSS:
- весь JS вынесен в `app.js`, задан строгий **CSP** `script-src 'self'` —
  любой встроенный/вставленный скрипт не выполняется;
- `connect-src` разрешает только запрос к поиску Diginetica;
- весь вывод данных **экранируется**, ссылки в href пропускаются только на `store.domeo.ru`.

На stage рекомендуется добавить HTTP-заголовки (их нельзя задать через `<meta>`):
`X-Frame-Options: DENY` (или `Content-Security-Policy: frame-ancestors 'none'`) и
`X-Content-Type-Options: nosniff`.

## Словарь соответствий и история (расширение)

Подтверждённые пары «артикул поставщика → товар DOMEO» копятся в браузере
(`chrome.storage.local`) и в следующий раз подставляются мгновенно («Из словаря»).
Схема для переноса на .NET-бэкенд (общий словарь на всех менеджеров):

```
match_dict(supplier, supplier_code, domeo_id, domeo_name, confirmed_by, confirmed_at)
  PRIMARY KEY (supplier, supplier_code)
order_history(id, created_at, manager, source, positions_count, total)
order_history_item(order_id, raw_name, qty, supplier_code, domeo_id, domeo_name, price, status)
```

## Ограничения

- Сайты поставщиков под антиботом — читать корзину можно только в браузере менеджера.
- Сборку корзины DOMEO стоит делать под логином менеджера (клубные цены, оформление заказа).
- Подбор на сложных позициях даёт статус «Проверить» — финальное слово за менеджером.
- `apiKey` Diginetica — публичный ключ store.domeo.ru (встроен в JS сайта), не секрет.
